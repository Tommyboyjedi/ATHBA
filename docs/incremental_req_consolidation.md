# Optional incremental completed-REQ consolidation

After a REQ is durably completed through TDD and Behavior Review, one checkpoint
considers it with at most one dependency/source-related active accepted group.
Relatedness only selects a bounded candidate; it never establishes equivalence.
No partner, oversized context, unsupported syntax, NO, semantic rejection or failed
unchanged-production execution leaves the accepted baseline unchanged and advances
ordinary delivery. There is one proposal and one test submission, with at most one
corrective submission per response. One complete outer unlabelled/JSON Markdown
fence is presentation only and consumes no correction. Other ambiguous wrappers,
prose, duplicate keys and schema violations remain rejected. A valid coverage
subset with source accepted by the configured authoring adapter may receive one
metadata-only completion using the original selected evidence and exact missing
references; source and existing entries are immutable.
This shares the existing correction slot with format correction, not another retry.
Raw replies and initial/corrective validation results remain journaled. Corrections
cannot rewrite recovered test source or change decisions. No Developer, Planner repair or alternate-partner
search is introduced.

The dedicated reasoning inputs contain only selected obligations/source clauses,
exact accepted tests, opaque fragment references and the existing authoring
descriptor. The original cases, preconditions, inputs, results, explicit errors
and state-preservation observations must survive independent semantic review.
A complete coverage reference map and GREEN alone are not equivalence proof.
Ordinary Tester/Developer prompts and Gatekeeper acceptance criteria are unchanged.

## Explicit evidence supersession

Original completed REQs and microcycle revisions remain immutable. The replacement
is approved GREEN evidence, with no invented RED or Developer attempt. Durable
supersession records retain original IDs/source refs/test hashes, replacement
hashes, coverage, semantic and execution evidence, unchanged-production validation
revision, reducer evidence and final revision. The current physical suite contains
the replacement plus unaffected tests. A shared resolver supplies those active
tests to subsequent regression, final Gatekeeper and post-behavior entry; full
original specification authority still belongs to Gatekeeper.

## Test-only checkpoint, then production reduction

An isolated test-only descendant must retain exact production/configuration and
unselected tests. Existing language validation and structured test execution verify
the replacement and every unaffected accepted node actually execute; full regression
also passes. Tests are frozen before production reduction. Execution uncertainty or
integrity corruption fails closed; it is never reported as an optional success.

The existing deterministic reducer then uses the same 24-trial/120-second bounds
and cleanup/restart handling. Its completion authority records actual approved
tests, without frontier RED fields. Ordered immutable contribution windows identify
selected additions; interleaved/shared/ambiguous material and existing explicitly
required declaration headers remain protected. An old baseline alone never grants
scope. Zero retained reductions may still publish valid test consolidation.

A verified pair is journaled before existing exact-base CAS/project synchronization
and atomic feature supersession publication. The checkpoint resumes before next-REQ
selection; pending uncertain reasoning is not resubmitted. Ordinary attempt counts
and completion histories are unchanged. A lifecycle event describes the optional
checkpoint without claiming another RED/GREEN cycle.

## Initial limitations

Selection is dependency/source-reference based, at most eight original REQs, with
32 KiB selected context and 64 KiB complete reasoning envelopes. A replacement uses
the existing one-ordinary-test grammar and one existing test module/production path;
independent cases can use separate setup in that function. Other shapes decline.
The first completion-scope syntax capability conservatively deletes unambiguous
owned additions; baseline restoration and ambiguous cross-scope transformations
are skipped. Unresolved/ambiguous required declarations (including absent future
APIs or owner-name differences awaiting Naming) yield zero production opportunities,
not a TDD failure. Partial/missing provenance fails closed. Greedy reduction does not
prove global minimality. Naming and the late Refactorer remain unchanged.
