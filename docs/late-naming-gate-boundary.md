# Preserve the late lexical Naming boundary

A typed lexical naming checklist obligation is delegated to post-behavior Naming. Gatekeeper retains the complete original source and the source-grounded delegation record; NOT_APPLICABLE/deferred_to_naming does not claim the name is already satisfied. Domain and Naming delegations are accepted only after revalidating the same original source and policy. Behavioral or provenance failures cannot borrow a delegation record.

Final signature assurance passes snapshot completeness into the existing declaration adapter. An unresolved source-spelled operation or owning declaration is uncertain, not proof of either the required call shape or an implementation violation. Multiple declarations are similarly uncertain. A single established declaration with wrong arity/defaults remains a blocking violation. The strict findings API still includes uncertainties and remains fail-closed.

Existing late Naming checks already reject NO for unresolved source-signature operations/parameters. They now also reject NO for a missing explicitly required non-signature identifier. Positive rename safety, accepted regression tests, revision checks and promotion guards remain unchanged. No new application semantics or Developer authority are introduced.

This corrects the interaction between typed obligation classification, final signature assurance and the existing late Naming stage. It is not a new planner or alternate repair path.
