# Recursive Behavioral Planner atomisation

This contract supersedes historical requirement-replacement and behavioral checklist-split routing.
After Behavioral Planner emits a valid source-grounded obligation, failure to deliver that
obligation returns to the same Planner after the stage's bounded local attempts.

## One semantic return
Tester submission/candidate/Intent failure consumes the existing four-attempt lineage.
Developer failure consumes the existing four attempts on the accepted RED.
Behavior Review may request bounded local repair or return directly for atomisation.
Exhausted behavior repair and regression repair return through the same feature admission
(strict_tdd_feature_replan.require_replan). Invalid frontier syntax and failure before the
selected frontier return as failed delivery, without handing invalid RED to Developer.
Each child executes through the ordinary Tester/Developer/review pipeline and may return again.

The request carries the exact parent, its source clauses, relevant failure summary/evidence
references, trusted revision and atomisation ancestry. It excludes whole-feature source,
completed behavior bodies and Tester transcripts. Accepted tests/revisions remain immutable;
pending dependents inherit the replacement children. Completed obligations are not rewritten.

## Independent Gatekeeper, shared delivery
Gatekeeper still receives the full original specification and independently evaluates the
trusted completed revision. A valid behavioral NO becomes a remaining source-grounded parent,
then enters the same Behavioral Planner. Gatekeeper never supplies a hand-authored replacement
test or a signature-specific work pipeline. Evidence producers can identify source obligations
using the same remaining_obligations checklist-item representation.

Behavioral checklist NOs no longer recursively recheck existing tests through a second
behavioral splitter. Mechanical assurance conjunctions retain their bounded exact partition
and independent verification. Assurance confidence/policy is unchanged; unsupported assurance
is never presented as proved. Missing language capability, incomplete authority, malformed
response or infrastructure prevents a semantic delivery decision and fails closed.

## Explicit non-semantic boundaries
Upstream failures before a valid obligation stay upstream. Infrastructure/non-execution,
protocol correction exhaustion and mechanical identity/revision/write violations do not
atomise. Executor-reported write evidence is checked before recording a semantic attempt.
Post-behavior Naming/Refactoring remain late, bounded and behavior-preserving.

Tester still receives only selected behavior authority. Developer still receives accepted
RED/failure evidence and production-only responsibility. No global requirement, naming,
assurance or Gatekeeper instruction is added to either role.

## Atomisation is not atomicity
Planner can produce a split, report no proposal, or report insufficient source authority.
One bounded correction shares the same parser/validation; raw attempts are retained.
Malformed output, invalid split, correction failure, interrupted/provider submission and
tree/child safety budgets have explicit failure outcomes. None is UNSPLITTABLE.

There is no validated genuine-atomic producer in the current architecture. A model assertion
that an obligation is atomic is not proof. Absence of a valid split is recorded as failure
to obtain atomisation, with atomicity explicitly unproven. Source-insufficient is also a
Planner report, not a deterministic proof that the source is insufficient.

Structural checks preserve refs, source coverage, modality/error authority, dependency and
ancestry constraints and reject unchanged/repeated outcomes. They are not a deterministic
proof of semantic equivalence or a globally decreasing semantic complexity measure. Finite
tree budgets bound execution, and independent reconciliation retains original authority.

## Language capability boundary
Generic orchestration requests test material, accepted-test extraction, syntax/acceptance
commands, specification evidence, parameter naming, production slicing and mutation authority
through injected capabilities. Production composition selects the existing Python implementations.
No new Python application semantics are introduced.

## Persisted-state transition
Microcycle schema 3 persists return_to_behavioral_planner. Atomisation request schema
behavior-atomisation/v2 persists concise failure authority and ancestry. Obsolete nonempty
requirement/specification repair records and old behavioral checklist split trees require
explicit migration. Old atomisation request schemas and microcycle schemas are rejected.
Historical qualification evidence remains untouched; it need not be executable by this flow.

## Review and qualification
All pre-merge validation uses deterministic fakes and disposable repositories.
Live qualification is deliberately deferred until operator architecture review and merge.
